# Почему падали фото / видео / анимация и что исправлено

**Кратко:** текст и лендинг работали, потому что им достаточно «отправить промпт и
дождаться текста/кнопки Download». Все медиа-режимы падали на двух местах:
**(1) промпт вообще не уходил** (модалка Terms of Use блокировала composer, а клик по
кнопке отправки уходил в промежуточный экран безопасности) и **(2) результат не
забирался** (код искал текстовую кнопку «Download» и `expect_download`, тогда как в
карточке результата Arena это иконка, а сам файл надёжнее тянуть из сети).

## Что именно было сломано

| # | Проблема | Последствие |
|---|----------|-------------|
| 1 | `generate_image()` ловил исключение и **не делал `raise`** → возвращал `None` | бот не отправлял ни файла, ни ошибки; токены списывались, в чат приходило только «Генерирую...» |
| 2 | Модалка **Terms of Use & Privacy Policy** держит composer выключенным: `accept_terms()` жал `Escape` и `button:has-text("Agree")`, но не проверял, что модалка действительно закрылась | промпт не отправлялся, дальше был тихий таймаут |
| 3 | Баннер «…**hit Enter on your keyboard to agree**» **съедает Enter** | нажатия Enter уходили в закрытие модалки, а не в отправку промпта |
| 4 | `submit_prompt()` всегда возвращал `True` и проверял старт генерации только по кнопке «Stop» | ошибка отправки не обнаруживалась, время уходило в таймаут |
| 5 | `wait_for_video()` требовал **двух** видимых кнопок с текстом «Download» | в реальном UI кнопка скачивания — иконка (`aria-label="Download"`), рядом с ней кнопка `Edit`; в итоге «Video generation timed out» |
| 6 | `wait_for_image()` умел только `expect_download` + скриншот элемента | при отсутствии кнопки «Download» результат не забирался |
| 7 | Селекторы были «generic» (`textarea`, `button:has(svg)`) | могли попадать в чужие элементы (поиск, меню модели и т.п.) |

## Что сделано

### 1. Согласие и модалки (`ensure_consent`)
* Новая проверка `consent_gate_open()` — ищет видимые `[role=dialog]` с текстом
  «Terms of Use / Privacy Policy / hit Enter on your keyboard to agree / manage cookie
  preferences».
* Закрытие: JS-клик по безопасным подписям (`Agree`, `I Agree`, `Accept Cookies`,
  `Accept All Cookies`, `Save Preferences`, `Got it`), затем Enter как резерв,
  затем клик по телу страницы + Enter. До 3 попыток.
* После согласия **страница перезагружается** — на arena.ai composer включается только
  после reload, а cookie `cookie-preferences` сохраняется в `cookies/arena_cookies.json`.
* Всплывающие «Got it» баннеры закрываются при каждой проверке ожидания.

### 2. Отправка промпта (`submit_prompt`)
* Порядок попыток: **Enter** → кнопка `button[aria-label="Send message"]` /
  `form:has(textarea) button[type=submit]` → закрыть согласие и повторить (3 круга).
* Успех отправки **проверяется** (`_wait_submission`): кнопка
  `aria-label="Stop generation"` / текст «Generating|Creating|Rendering» / текст
  промпта появился в переписке / уход на `/c/…` с пустым composer.
* Если промпт так и не ушёл — исключение (бот вернёт токены и напишет об ошибке).

### 3. Ввод промпта и вложения
* Точечные селекторы: `textarea[placeholder^='Describe the image']` (картинки),
  `textarea[placeholder*='Describe your video']` (видео), generic — как резерв.
* Ввод через `fill()` с проверкой значения, затем клавиатура, затем JS-setter.
* Вложение файла: кнопка **Add files** → `filechooser.set_files()` → резерв
  `input[type=file]` (в т.ч. принудительно) → понятная ошибка, если ничего не нашли.

### 4. Получение результата (5 стратегий, в порядке приоритета)
1. **Перехват сети**: ответы с `content-type: image/* | video/*` (и по расширению)
   складываются в список кандидатов, иконки/логотипы/аватарки отсекаются.
2. **SSE-поток** `POST /nextjs-api/stream`: строки `a2:{…}` содержат прямые URL
   результата, `a3:` (ошибка провайдера) и `ae:` (ошибка платформы/модерации) — их
   текст попадает в сообщение об ошибке.
3. **Кнопки скачивания**: ищутся кнопки/ссылки с «download» **и** кнопка-иконка слева
   от кнопки «Edit» (так устроена карточка результата Arena), клик + ловля
   download-событий (`page.on("download")`), сохранение файла.
4. **Скачивание найденного URL** через `page.request.get()` (наследует cookies,
   подписанные CDN-ссылки) и резервный `fetch()` внутри страницы (для `blob:`/`data:`).
5. Последний резерв — скриншот элемента изображения.

Дополнительно: перед генерацией запоминаются уже имеющиеся картинки (baseline), чтобы
не отдать пользователю старый результат; слишком маленькие ответы (<2 КБ для картинок,
<20 КБ для видео) считаются мусором.

### 5. Прочее
* Кнопка генерации/остановки проверяется по `aria-label="Stop generation"`.
* `_navigate_and_wait` умеет возвращаться на direct-страницу, если Arena
  редиректнула на battle/root.
* Таймауты вынесены в `config.py`: `IMAGE_TIMEOUT=600`, `VIDEO_TIMEOUT=1800`,
  `TEXT_TIMEOUT=300`, `ARENA_VIDEO_VARIANTS=2` (можно переопределить в `.env`).
* Бот: если генератор вернул пустой результат — исключение, токены возвращаются,
  пользователь получает сообщение об ошибке (раньше в этом случае не приходило ничего).

## Как проверить

```bash
# 1) Быстрые офлайн-тесты (фейковый Playwright, без браузера и без arena.ai)
pip install pytest pytest-asyncio python-dotenv
pytest -q tests/

# 2) Офлайн-прогон реального конвейера в настоящем Chromium:
#    поднимается локальный мок arena.ai (модалка Terms, textarea, Send message,
#    Stop generation, карточка результата с иконкой Download и кнопкой Edit)
python selftest_arena.py            # все режимы
python selftest_arena.py image      # только картинка
python selftest_arena.py video      # только видео
python selftest_arena.py edit animate
```

`selftest_arena.py` не тратит токены и не зависит от arena.ai — если он проходит,
значит механика (согласие → ввод → отправка → перехват → скачивание) на месте.

## Если снова что-то не работает

1. В логах ищите строки:
   * `⚠️ Найдена модалка согласия Arena` — согласие найдено;
   * `Generation started via Enter ✅` / `via button ✅` — промпт ушёл;
   * `Нажато кнопок скачивания: N` и `Download captured → …`;
   * `Downloaded … KB via context.request` — файл забран из сети;
   * `Не удалось отправить промпт…` — composer заблокирован (обычно протухли cookies).
2. Скриншоты `debug_image_error.png`, `debug_video_error.png`,
   `debug_animate_error.png`, `debug_image_edit_error.png` показывают состояние
   страницы в момент падения.
3. Обновить cookies: положить свежий `cookies/arena_cookies.json`
   (файл пишется автоматически после закрытия модалки согласия).
4. Если падает модерация — теперь приходит текст ошибки Arena (`a3:`/`ae:`),
   например `moderation_blocked`.

## Новые переменные окружения (все опциональны)

| Переменная | По умолчанию | Значение |
| :--- | :--- | :--- |
| `IMAGE_TIMEOUT` | `600` | таймаут картинок/редактирования, сек |
| `VIDEO_TIMEOUT` | `1800` | таймаут видео/оживления, сек |
| `TEXT_TIMEOUT` | `300` | таймаут текста, сек |
| `ARENA_VIDEO_VARIANTS` | `2` | сколько вариантов видео ждать |
| `ARENA_SUBMIT_CHECK_SECONDS` | `10` | сколько ждать подтверждения отправки |
| `ARENA_IMAGE_POLL_SECONDS` | `4` | интервал опроса результата (картинки) |
| `ARENA_VIDEO_POLL_SECONDS` | `8` | интервал опроса результата (видео) |
| `ARENA_DOWNLOAD_WAIT_SECONDS` | `25` | сколько ждать download-событие |
| `ARENA_DOWNLOAD_CLICK_SECONDS` | `20` | пауза между кликами по «скачать» |
| `ARENA_CONSENT_CHECK_SECONDS` | `15` | как часто перепроверять модалки |
